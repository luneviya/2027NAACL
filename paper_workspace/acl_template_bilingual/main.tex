\begin{abstract}
Neural code search systems are commonly trained with static hard negatives that need not reflect the high-ranked alternatives encountered after training. We propose \method{}, a failure-calibrated refinement framework that converts the initial retriever's own high-ranked unpaired candidates into targeted contrastive supervision. \method{} refines global query--code representations against these candidates and optionally reranks only the top-\(K\) results with a token-level MaxSim score. Under a unified local evaluation protocol on the six-language CodeSearchNet benchmark, refinement raises macro-averaged MRR from 79.8 to 80.6, while final reranking reaches 81.1. This corresponds to an absolute improvement of 1.3 MRR points over the initial retriever, with a 95\% confidence interval of [1.11, 1.47] estimated by paired bootstrap resampling over test queries. Candidate-selection controls and rank-stratified analyses locate the improvement in initially misranked queries, while three encoder instantiations examine the architectural scope of the framework.
% 中文：神经代码检索系统通常使用静态困难负样本进行训练，但这些样本未必能反映模型完成训练后实际返回的高排名替代候选。本文提出 \method{}，一种失败校准的细化框架，将初始检索器自身产生的高排名未配对候选转化为有针对性的对比监督。\method{} 利用这些候选细化全局查询—代码表示，并可选地使用词元级 MaxSim 分数仅对前 \(K\) 个结果进行重排。在六语言 CodeSearchNet 基准上的统一本地评测协议下，全局细化将宏平均 MRR 从 79.8 提升到 80.6，最终重排进一步达到 81.1。相对于初始检索器，这对应 1.3 个 MRR 绝对点数的提升；在测试查询上进行配对 bootstrap 重采样后，95\% 置信区间为 [1.11, 1.47]。候选选择对照和按排名分层的分析将收益定位于初始排序错误的查询，三个编码器实例化实验则考察该框架的架构适用范围。
\end{abstract}

\section{Method}
\label{sec:method}

\method{} organizes retrieval refinement into three stages. Failure Candidate Harvesting first exposes the high-ranked unpaired alternatives produced by a frozen initial retriever. Failure-Calibrated Contrastive Refinement then uses these model-specific candidates to update the global retrieval space. At inference time, the refined dual encoder searches the complete corpus, after which optional Dual-Granularity Reranking combines sequence-level and token-level evidence within a compact top-\(K\) set.
% 中文：\method{} 将检索细化组织为三个阶段。失败候选挖掘首先暴露冻结初始检索器产生的高排名未配对替代项；失败校准对比细化随后利用这些模型特定候选更新全局检索空间。推理时，细化后的双编码器先搜索完整语料库，可选的双粒度重排再在紧凑的前 \(K\) 候选集合内融合序列级与词元级证据。

\subsection{Problem Formulation}
\label{sec:problem_formulation}

Let \(\mathcal{D}=\{(q_i,c_i^+)\}_{i=1}^{N}\) denote a code-search training set, where \(q_i\) is a natural-language query and \(c_i^+\) is its paired code snippet. A dual encoder maps queries and code into a shared space through \(f_\theta\) and \(g_\theta\). After \(\ell_2\) normalization, their global retrieval score is
% 中文：设 \(\mathcal{D}=\{(q_i,c_i^+)\}_{i=1}^{N}\) 表示代码搜索训练集，其中 \(q_i\) 是自然语言查询，\(c_i^+\) 是与之配对的代码片段。双编码器分别通过 \(f_\theta\) 和 \(g_\theta\) 将查询与代码映射到共享空间。经过 \(\ell_2\) 归一化后，其全局检索分数定义为
\begin{equation}
  s_\theta(q,c)=f_\theta(q)^{\top}g_\theta(c).
  \label{eq:global_score}
\end{equation}

For a competing candidate \(c^-\), define the score margin as \(\mu_\theta(q_i,c^-)=s_\theta(q_i,c_i^+)-s_\theta(q_i,c^-)\). The rank of the paired code can then be written as
% 中文：对于竞争候选 \(c^-\)，定义分数间隔 \(\mu_\theta(q_i,c^-)=s_\theta(q_i,c_i^+)-s_\theta(q_i,c^-)\)。配对代码的排名可写为
\begin{equation}
  \operatorname{rank}_\theta(c_i^+\mid q_i)
  =1+\sum_{c\in\mathcal{C}\setminus\{c_i^+\}}
  \mathbb{I}\!\left[\mu_\theta(q_i,c)\leq 0\right],
  \label{eq:rank_margin}
\end{equation}
where \(\mathcal{C}\) is the retrieval corpus. Equation~\ref{eq:rank_margin} makes the relevant supervision target explicit: ranking errors are determined by candidates whose scores meet or exceed that of the paired code. Because conventional in-batch or statically mined negatives are selected before the final retriever is observed, they need not coincide with these model-specific competitors. \method{} therefore conditions refinement on the ranking behavior of a trained initial retriever.
% 中文：其中 \(\mathcal{C}\) 表示检索语料库。式~\ref{eq:rank_margin} 明确了与排序直接相关的监督对象：排序错误由得分达到或超过配对代码的候选决定。常规批内负例或静态挖掘负例是在最终检索器行为被观察之前选取的，因此未必与这些模型特定的竞争候选一致。基于此，\method{} 根据训练完成的初始检索器所产生的排序行为开展细化。

\subsection{Failure Candidate Harvesting}
\label{sec:failure_harvesting}

We first train an initial retriever with the underlying contrastive code-search objective and freeze its parameters \(\theta_0\). For every training query, the frozen model retrieves from the training code corpus. Let \(\mathcal{E}_i\) contain the paired code and all candidates sharing its URL. We remove \(\mathcal{E}_i\) and retain the \(M\) highest-scoring candidates:
% 中文：我们首先使用基础对比式代码搜索目标训练初始检索器，并冻结其参数 \(\theta_0\)。对于每个训练查询，冻结模型在训练代码语料库中执行检索。令 \(\mathcal{E}_i\) 包含配对代码以及与其共享 URL 的所有候选；移除 \(\mathcal{E}_i\) 后，保留得分最高的 \(M\) 个候选：
\begin{equation}
  \mathcal{H}_i=
  \operatorname{Top}_{M}^{s_{\theta_0}(q_i,\cdot)}
  (\mathcal{C}_{\mathrm{train}}\setminus\mathcal{E}_i),
  \qquad
  \mathcal{F}_i=
  \operatorname{Top}_{m}^{s_{\theta_0}(q_i,\cdot)}(\mathcal{H}_i).
  \label{eq:fc_pool}
\end{equation}

We call members of \(\mathcal{F}_i\) \emph{failure candidates}: they are the initial retriever's strongest unpaired alternatives for \(q_i\), and hence directly instantiate the score comparisons implicated by Equation~\ref{eq:rank_margin}. This is an operational designation based on benchmark pairing and retrieval rank; it does not assume that every unpaired candidate is semantically invalid. The pool is generated once from the frozen initial retriever. During refinement, we sample \(r\) candidates from its top \(m\) entries for each query, preserving model specificity without repeating corpus-wide retrieval at every update.
% 中文：我们将 \(\mathcal{F}_i\) 中的元素称为“失败候选”：它们是初始检索器针对 \(q_i\) 返回的最强未配对替代项，因此直接对应式~\ref{eq:rank_margin} 所涉及的分数比较。该名称是依据基准配对关系和检索排名给出的操作性定义，并不假设每个未配对候选在语义上都无效。候选池仅由冻结的初始检索器生成一次；细化时，每个查询从池中排名前 \(m\) 的条目中采样 \(r\) 个候选，从而保留模型特异性，同时避免在每次参数更新时重复执行全语料库检索。

\subsection{Failure-Calibrated Contrastive Refinement}
\label{sec:failure_refinement}

Starting from \(\theta_0\), we retain the initial retriever's contrastive objective \(\mathcal{L}_{\mathrm{base}}\) and introduce a listwise objective over the harvested candidates. For a minibatch \(\mathcal{B}\), let \(\mathcal{S}_i\subseteq\mathcal{F}_i\) contain the \(r\) candidates sampled for query \(q_i\). The failure-candidate loss is
% 中文：以 \(\theta_0\) 为起点，我们保留初始检索器的对比目标 \(\mathcal{L}_{\mathrm{base}}\)，并对挖掘得到的候选引入 listwise 目标。对于小批量 \(\mathcal{B}\)，设 \(\mathcal{S}_i\subseteq\mathcal{F}_i\) 包含为查询 \(q_i\) 采样的 \(r\) 个候选。失败候选损失定义为
\begin{equation}
  \mathcal{L}_{\mathrm{FC}}^{i}
  =-\log\frac{\exp(s_\theta(q_i,c_i^+)/\tau_f)}
  {\exp(s_\theta(q_i,c_i^+)/\tau_f)
   +\sum_{c\in\mathcal{S}_i}\exp(s_\theta(q_i,c)/\tau_f)},
  \label{eq:fc_loss}
\end{equation}
and the complete refinement objective is
% 中文：完整的细化目标为
\begin{equation}
  \mathcal{L}_{\mathrm{ref}}
  =\mathcal{L}_{\mathrm{base}}
  +\frac{\lambda_f}{|\mathcal{B}|}
   \sum_{i\in\mathcal{B}}\mathcal{L}_{\mathrm{FC}}^{i}.
  \label{eq:refinement_loss}
\end{equation}

The added term admits a direct score-margin form,
% 中文：新增损失项可直接写成分数间隔形式：
\begin{equation}
  \mathcal{L}_{\mathrm{FC}}^{i}
  =\log\!\left(1+\sum_{c\in\mathcal{S}_i}
  \exp[-\mu_\theta(q_i,c)/\tau_f]\right).
  \label{eq:margin_loss}
\end{equation}
Candidates with smaller or negative margins consequently exert greater optimization pressure, while \(\lambda_f\) calibrates this targeted signal against the initial retriever's training objective. The refinement stage operates only on global representations and introduces neither a token-level local-interaction loss nor an auxiliary CTRD objective.
% 中文：因此，分数间隔更小或为负的候选会产生更强的优化压力，而 \(\lambda_f\) 用于校准这一针对性信号相对于初始检索器训练目标的权重。细化阶段仅作用于全局表示，不引入词元级局部交互损失，也不使用辅助 CTRD 目标。

\subsection{Dual-Granularity Reranking}
\label{sec:reranking_method}

Global retrieval remains responsible for searching the complete corpus. To resolve fine-grained distinctions only where they can affect the returned ranking, we optionally rescore its top-\(K\) candidates with MaxSim~\citep{ColBERT}. Let \(\{\mathbf{h}^{q}_{a}\}_{a=1}^{T_q}\) and \(\{\mathbf{h}^{c}_{b}\}_{b=1}^{T_c}\) be the token representations of a query and candidate code. Their local-interaction score is
% 中文：全局检索仍负责在完整语料库中进行搜索。为了仅在可能影响最终排名的位置解析细粒度差异，我们可选地使用 MaxSim~\citep{ColBERT} 对其前 \(K\) 个候选重新计分。设 \(\{\mathbf{h}^{q}_{a}\}_{a=1}^{T_q}\) 和 \(\{\mathbf{h}^{c}_{b}\}_{b=1}^{T_c}\) 分别为查询与候选代码的词元表示，其局部交互分数为
\begin{equation}
  s_m(q,c)=\frac{1}{T_q}\sum_{a=1}^{T_q}
  \max_{1\leq b\leq T_c}
  \cos(\mathbf{h}^{q}_{a},\mathbf{h}^{c}_{b}).
  \label{eq:maxsim}
\end{equation}

Because global and token-level scores have different query-dependent scales, each is standardized over the same top-\(K\) set. The final score is
% 中文：由于全局分数与词元级分数具有不同且依赖查询的数值尺度，我们在同一前 \(K\) 候选集合内分别对二者进行标准化。最终分数定义为
\begin{equation}
  s_r(q,c)=\alpha\widetilde{s}_\theta(q,c)
  +(1-\alpha)\widetilde{s}_m(q,c).
  \label{eq:fusion}
\end{equation}
Only candidates inside the top-\(K\) set are reordered; all remaining corpus items preserve their global-retrieval order. This stage adds no trainable parameters and is selected independently from the training objective. It does, however, incur token-level inference cost, which we measure explicitly in Section~\ref{sec:efficiency}.
% 中文：只有前 \(K\) 集合内的候选会被重新排序，其余语料库条目保持全局检索产生的顺序。该阶段不增加可训练参数，并与训练目标独立选择；但它会带来词元级推理开销，我们在第~\ref{sec:efficiency} 节中对此进行显式测量。

\section{Experiments}
\label{sec:experiments}

We evaluate \method{} along three complementary dimensions. First, we benchmark its retrieval effectiveness against representative code-search systems and the matched initial retriever, and examine its transfer across encoder architectures. Second, budget-matched candidate-selection controls and a \(2\times2\) training--inference comparison disentangle the gains attributable to retriever-mined candidates from those due to continued optimization or generic top-\(K\) reranking. Third, paired bootstrap confidence intervals, analyses stratified by initial rank, and latency and peak-memory measurements characterize query-sampling uncertainty, ranking behavior, and computational overhead.
% 中文：我们从三个相互补充的维度评估 \method{}。首先，将其检索效果与具有代表性的代码搜索系统及协议一致的初始检索器进行比较，并考察其在不同编码器架构之间的迁移能力。其次，通过预算一致的候选选择对照以及 \(2\times2\) 训练—推理比较，区分检索器挖掘候选带来的收益、继续优化产生的影响以及通用前 \(K\) 重排的增益。最后，结合配对 bootstrap 置信区间、按初始排名分层的分析以及延迟和峰值显存测量，刻画查询采样不确定性、排序行为和计算开销。

\paragraph{Implementation and controlled comparisons.}
Our primary experiments use CoCoSoDa~\citep{CoCoSoDa} as the encoder and adopt the training configuration of UA-HN~\citep{AAAIUA}. The initial retriever, \method{}-Global, and \method{}-Rerank are evaluated on identical data splits and retrieval corpora using the same metric implementation. In the candidate-selection controls, we fix the refinement schedule and the number of additional candidates per query, and vary only the selection strategy: a randomly sampled unpaired code snippet (Random), a fixed pre-mined hard negative (Static HN), or a high-ranked unpaired candidate mined by the frozen initial retriever (failure candidate; FC). Under the same candidate budget, this controlled design isolates the effect of candidate selection from that of additional optimization.
% 中文：主要实验采用 CoCoSoDa~\citep{CoCoSoDa} 作为编码器，并沿用 UA-HN~\citep{AAAIUA} 的训练配置。初始检索器、\method{}-Global 和 \method{}-Rerank 均在完全相同的数据划分和检索语料库上，使用同一套指标实现进行评测。在候选选择对照中，我们固定细化训练日程以及每个查询新增候选的数量，仅改变选择策略：随机采样的未配对代码片段（Random）、固定的预挖掘困难负例（Static HN），或由冻结初始检索器挖掘的高排名未配对候选（失败候选；FC）。这一受控设计在相同候选预算下，将候选选择的作用与额外优化的影响区分开来。

\paragraph{Training and model selection.}
We train the initial retriever for 10 epochs with a batch size of 128, a learning rate of \(8\times10^{-6}\), and a contrastive temperature of 0.03. To construct the FC pool, we freeze the validation-selected checkpoint and perform retrieval over the training corpus. After removing the paired code snippet and any candidate that shares its URL, we retain the 32 highest-ranked candidates (\(M=32\)). During refinement, we restrict this pool to the top eight candidates (\(m=8\)) and sample one candidate per query at each update (\(r=1\)). We train the refinement stage for three epochs with a batch size of 128, a learning rate of \(5\times10^{-6}\), an FC loss weight of 0.45, and an FC temperature of 0.03. The refinement objective operates exclusively on global query--code representations; neither CTRD nor a token-level local-interaction loss is used during training.
% 中文：初始检索器训练 10 个 epoch，批量大小为 128，学习率为 \(8\times10^{-6}\)，对比学习温度为 0.03。构造 FC 候选池时，我们冻结由验证集选定的检查点，并在训练语料库上执行检索。移除配对代码片段以及与其 URL 相同的所有候选后，保留排名最高的 32 个候选（\(M=32\)）。细化阶段将候选池限制为前 8 个候选（\(m=8\)），并在每次更新时为每个查询采样 1 个候选（\(r=1\)）。细化训练进行 3 个 epoch，批量大小为 128，学习率为 \(5\times10^{-6}\)，FC 损失权重为 0.45，FC 温度为 0.03。细化目标仅作用于全局查询—代码表示；训练过程中既不使用 CTRD，也不使用词元级局部交互损失。

At inference time, \method{}-Global performs standard dual-encoder retrieval over the full corpus. The optional reranker computes a parameter-free token-level MaxSim score only for the top-\(K\) candidates returned by global retrieval. It combines the per-query standardized global score \(\widetilde{s}_g\) and MaxSim score \(\widetilde{s}_m\) as \(\alpha\widetilde{s}_g+(1-\alpha)\widetilde{s}_m\). We select \(K=20\) and \(\alpha=0.5\) by maximizing macro-averaged MRR across the six validation sets, and fix both hyperparameters before test-set evaluation. Model checkpoints are likewise selected exclusively according to validation performance. Unless otherwise stated, all locally evaluated results use random seed 123456 and are obtained on a single NVIDIA H20 GPU.
% 中文：推理时，\method{}-Global 在完整语料库上执行标准双编码器检索。可选重排器仅对全局检索返回的前 \(K\) 个候选计算无额外训练参数的词元级 MaxSim 分数。它按照 \(\alpha\widetilde{s}_g+(1-\alpha)\widetilde{s}_m\) 融合逐查询标准化后的全局分数 \(\widetilde{s}_g\) 与 MaxSim 分数 \(\widetilde{s}_m\)。我们通过最大化六个验证集上的宏平均 MRR，选择 \(K=20\) 和 \(\alpha=0.5\)，并在测试集评测前固定这两个超参数。模型检查点同样完全依据验证集表现选择。除非另有说明，所有本地评测结果均使用随机种子 123456，并在单张 NVIDIA H20 GPU 上获得。

For the GraphCodeBERT instantiation, we preserve its data-flow-aware input representation and use maximum lengths of 128 natural-language tokens, 256 code tokens, and 64 data-flow nodes. The initial retriever is trained for 10 epochs with batch size 32 and learning rate \(2\times10^{-5}\); the three-epoch refinement uses batch size 128 and learning rate \(5\times10^{-6}\), with the same \(M=32\), \(m=8\), \(r=1\), and \(\lambda_f=0.45\) as the primary experiment. MaxSim is computed over lexical tokens and excludes data-flow nodes, so structural nodes do not spuriously participate in token matching.
% 中文：在 GraphCodeBERT 实例化中，我们保留其数据流感知输入表示，并将自然语言、代码和数据流节点的最大长度分别设为 128、256 和 64。初始检索器训练 10 个 epoch，批量大小为 32，学习率为 \(2\times10^{-5}\)；三轮细化采用 128 的批量大小和 \(5\times10^{-6}\) 的学习率，并沿用主要实验中的 \(M=32\)、\(m=8\)、\(r=1\) 与 \(\lambda_f=0.45\)。MaxSim 仅在词法词元上计算并排除数据流节点，从而避免结构节点不当地参与词元匹配。

\paragraph{Uncertainty estimates.}
We estimate 95\% confidence intervals for paired MRR differences using a stratified paired bootstrap over test queries. Because the bootstrap keeps the trained checkpoints fixed, these intervals quantify uncertainty due to the finite test sample rather than variability across independent training runs.
% 中文：我们在测试查询上采用分层配对 bootstrap，为配对 MRR 差值估计 95\% 置信区间。由于 bootstrap 过程中训练检查点保持固定，这些区间衡量的是有限测试样本带来的不确定性，而不是独立训练运行之间的变化。

The latency measurement therefore reflects the complete inference path rather than an oracle-assisted estimate: reranking is executed for every query regardless of whether the gold code snippet appears among the top-\(K\) candidates.

\section*{Limitations}

Our evidence is limited to CodeSearchNet and one audited training seed. The paired bootstrap intervals quantify uncertainty induced by the finite test sample, but they do not capture variation across independent retraining runs. CodeSearchNet also provides only one paired code snippet per query, so some high-ranked unpaired candidates may be valid alternative implementations; the operational term \emph{failure candidate} should not be interpreted as a semantic judgment. The encoder-instantiation experiments demonstrate end-to-end compatibility, but the absence of locally evaluated initial checkpoints under the same encoder-specific settings prevents protocol-matched estimates of their refinement gains. Finally, MaxSim introduces no trainable parameters but increases inference latency through top-\(K\) token interactions.
% 中文：当前证据仅覆盖 CodeSearchNet 和一个经过审计的训练随机种子。配对 bootstrap 区间衡量有限测试样本引起的不确定性，但不能反映独立重新训练之间的变化。CodeSearchNet 每个查询也只提供一个配对代码片段，因此部分高排名未配对候选可能是有效替代实现；“失败候选”这一操作性术语不应被理解为语义判断。编码器实例化实验说明完整流程具有端到端兼容性，但由于缺少相同编码器特定设置下的本地初始检查点评测，尚不能估计协议完全匹配的细化增益。最后，MaxSim 虽不增加可训练参数，却会因前 \(K\) 候选的词元交互而增加推理延迟。

\section{Reproducibility Details}

\paragraph{Pipeline audit.}
We verify data-split isolation, candidate-cache validity, checkpoint provenance, validation-only model selection, and test-set evaluation configurations before admitting a local result. There is no exact overlap in URLs, repositories, or normalized code across the training, validation, and test partitions, and the paired code is present in the retrieval corpus for every validation and test query. Each FC cache contains 32 unique candidates with valid training-corpus indices and excludes both the paired example and candidates sharing its URL. Reconstructing model selection from the stored validation results independently yields the same reranking configuration, \(K=20\) and \(\alpha=0.5\).
% 中文：在纳入本地结果前，我们核验数据划分隔离、候选缓存有效性、检查点来源、仅基于验证集的模型选择，以及测试集评测配置。训练集、验证集和测试集之间不存在 URL、代码仓库或规范化代码的精确重叠；每个验证和测试查询的配对代码都存在于检索语料库中。每个 FC 缓存包含 32 个唯一且训练语料库索引有效的候选，并排除配对样本以及与其 URL 相同的候选。根据保存的验证集结果独立重建模型选择过程后，得到相同的重排配置，即 \(K=20\)、\(\alpha=0.5\)。

The GraphCodeBERT run is subjected to the same corpus-coverage and candidate-cache checks. These checks are completed before aggregating the language-level test files.
