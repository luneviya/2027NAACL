\begin{abstract}
Dual-encoder code search enables efficient full-corpus retrieval, but standard contrastive training need not expose the model to the high-scoring candidates that determine the paired code's rank at inference time. This mismatch is especially relevant in Retrieved-but-Mis-ranked Cases, where the paired code is already near the top but remains below one or more competing snippets. We introduce \method{} (Retriever Feedback for Code Search), a second-stage framework that freezes the initial retriever and converts its full-corpus rankings into fixed, query-specific Failure Candidate Pools. Failure-Calibrated Contrastive Refinement applies a separate contrastive loss to candidates in these pools, assigning stronger optimization pressure to smaller or negative positive--negative score margins while retaining efficient global retrieval. This training procedure yields \method{}-Global; \method{}-Rerank further applies Dual-Granularity Reranking within the retrieved top-\(K\) by fusing global and token-level MaxSim scores. Under a matched six-language CodeSearchNet protocol, \method{}-Global raises macro MRR from 79.8 to 80.6, and \method{}-Rerank reaches 81.1. Budget-matched controls favor retriever-harvested candidates over random and static alternatives, while rank-conditioned analysis locates the largest gains at initial ranks 2--10.
% 中文：双编码器代码搜索能够实现高效的全库检索，但标准对比训练未必会让模型接触到那些在推理时决定配对代码排名的高分候选。这种错位在“已检索但排序错误案例”（Retrieved-but-Mis-ranked Cases）中尤其相关：配对代码已经接近顶部，却仍排在一个或多个竞争代码片段之后。本文提出 \method{}（Retriever Feedback for Code Search），一种第二阶段框架：冻结初始检索器，并将其全库排序转化为固定的、逐查询的失败候选池（Failure Candidate Pools）。失败校准对比细化（Failure-Calibrated Contrastive Refinement）对候选池中的条目计算独立的对比损失，在保留高效全局检索的同时，对正负样本分数间隔较小或为负的候选施加更强优化压力。该训练流程得到 \method{}-Global；\method{}-Rerank 进一步在检索得到的前 \(K\) 个候选内执行双粒度重排（Dual-Granularity Reranking），融合全局分数与词元级 MaxSim 分数。在六语言 CodeSearchNet 的协议一致评测中，\method{}-Global 将宏平均 MRR 从 79.8 提升至 80.6，\method{}-Rerank 达到 81.1。预算匹配的对照表明，检索器挖掘候选优于随机和静态替代方案；按排名分层的分析将最大收益定位于初始第 2--10 名。
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Code search maps natural-language intent to executable implementations and supports program comprehension and reuse~\citep{CodeSearchSurvey}. Many neural code-search systems use a dual-encoder architecture: they encode queries and code independently, then rank the corpus by similarity in a shared representation space~\citep{CodeBERT,GraphCodeBERT,UniXcoder}. This dual-encoder design enables efficient full-corpus retrieval, while contrastive pre-training and fine-tuning align paired queries and code~\citep{CodeRetriever,CoCoSoDa}.
% 中文：代码搜索将自然语言意图映射到可执行实现，并为程序理解与复用提供支持~\citep{CodeSearchSurvey}。许多神经代码搜索系统采用双编码器架构：它们分别编码查询与代码，再根据共享表示空间中的相似度对语料库进行排序~\citep{CodeBERT,GraphCodeBERT,UniXcoder}。这种双编码器设计支持高效的全库检索，对比式预训练与微调则对齐配对查询和代码~\citep{CodeRetriever,CoCoSoDa}。

Contrastive code-search objectives optimize each query against a sampled set of competitors. At inference time, however, the paired code's rank is determined by the corpus items that the trained retriever scores at least as highly. Minibatch, random, and static negatives are constructed without access to the trained retriever's query-specific full-corpus ranking and therefore need not include the candidates responsible for its observed mis-rankings. Figure~\ref{fig:problem_setting} illustrates a Retrieved-but-Mis-ranked Case in which the paired code is already near the top but remains below one or more high-scoring unpaired candidates. This mismatch between sampled training competitors and rank-determining inference candidates motivates using the frozen initial retriever's rankings as feedback for a separate refinement stage.
% 中文：对比式代码搜索目标针对采样得到的竞争候选优化每个查询。然而在推理时，配对代码的排名由训练后检索器赋予不低于其得分的语料项决定。批内、随机和静态负例在构造时无法利用训练后检索器的逐查询全库排序，因此未必包含造成其实际错排的候选。图~\ref{fig:problem_setting} 展示了一个“已检索但排序错误案例”（Retrieved-but-Mis-ranked Case）：配对代码已经接近顶部，却仍位于一个或多个高分未配对候选之后。采样训练竞争项与决定推理排名的候选之间的这种错位，促使我们将冻结初始检索器的排序作为独立细化阶段的反馈。

We therefore propose \method{} (Retriever Feedback for Code Search), a three-stage framework driven by the fixed rankings of a trained retriever. \textbf{Failure Candidate Harvesting} excludes the paired example and same-URL candidates, then converts the remaining high-ranked results into a query-specific \textbf{Failure Candidate Pool}. \textbf{Failure-Calibrated Contrastive Refinement} applies a separately weighted contrastive loss to that pool while preserving the base objective. Its positive--negative score-margin form gives candidates with smaller or negative margins greater optimization pressure. These two stages produce \method{}-Global, which retains full-corpus dual-encoder retrieval. \method{}-Rerank enables \textbf{Dual-Granularity Reranking}, which computes token-level MaxSim scores and combines them with global retrieval scores through Global--Local Score Fusion within the retrieved top-\(K\).
% 中文：为此，我们提出 \method{}（Retriever Feedback for Code Search），一种由训练完成的检索器固定排序驱动的三阶段框架。\textbf{失败候选挖掘（Failure Candidate Harvesting）}排除配对样本和同 URL 候选，再将其余高排名结果转化为逐查询的\textbf{失败候选池（Failure Candidate Pool）}。\textbf{失败校准对比细化（Failure-Calibrated Contrastive Refinement）}保留基础目标，并对该候选池计算单独加权的对比损失。其正负样本分数间隔形式使间隔较小或为负的候选产生更强优化压力。这两个阶段得到保留全库双编码器检索的 \method{}-Global。\method{}-Rerank 启用\textbf{双粒度重排（Dual-Granularity Reranking）}：它在检索得到的前 \(K\) 个候选内计算词元级 MaxSim 分数，并通过全局—局部分数融合（Global--Local Score Fusion）将其与全局检索分数结合。

In a protocol-matched local evaluation across all six CodeSearchNet languages~\citep{CodeSearchNet}, \method{}-Global raises macro MRR from 79.8 to 80.6 and R@1 from 70.7 to 71.9; \method{}-Rerank reaches 81.1 MRR and 72.6 R@1. Controlled comparisons favor retriever-mined Failure Candidates over random and static alternatives, with the largest gains concentrated in near-top misrankings (initial ranks 2--10).
% 中文：在覆盖全部六种 CodeSearchNet 语言~\citep{CodeSearchNet}的协议一致本地评测中，\method{}-Global 将宏平均 MRR 从 79.8 提升至 80.6，并将 R@1 从 70.7 提升至 71.9；\method{}-Rerank 达到 81.1 MRR 和 72.6 R@1。受控比较表明，检索器挖掘的失败候选优于随机和静态替代方案，且最大收益集中在接近顶部的排序错误案例中，即配对代码的初始排名为第 2--10 位时。

\section{Related Work}
\label{sec:related_work}

\subsection{Code Search}

Code search evolved from lexical and structural matching to neural systems that learn shared query--code representations~\citep{CodeHow,DeepCS}. Pre-trained dual encoders incorporate bimodal context, data flow, and unified cross-modal learning while retaining efficient full-corpus retrieval~\citep{CodeBERT,GraphCodeBERT,UniXcoder}. Contrastive approaches strengthen query--code alignment through syntax-guided objectives, multimodal pre-training, augmentation, momentum encoders, and semantics-preserving transformations~\citep{SynCoBERT,CodeRetriever,CoCoSoDa,Corder,ContraCode,ContraBERT}.
% 中文：代码搜索已经从词法和结构匹配发展到学习共享查询—代码表示的神经系统~\citep{CodeHow,DeepCS}。预训练双编码器在保持高效全语料库检索的同时，将双模态上下文、数据流和统一跨模态学习引入这些表示~\citep{CodeBERT,GraphCodeBERT,UniXcoder}。对比式方法则通过语法引导目标、多模态预训练、数据增强、动量编码器和语义保持变换，进一步加强查询与代码之间的对齐~\citep{SynCoBERT,CodeRetriever,CoCoSoDa,Corder,ContraCode,ContraBERT}。

Negative-aware objectives alter the competitors used in contrastive learning. Soft-InfoNCE weights negatives by estimated relevance~\citep{SoftInfoNCE}. Uncertainty-aware training combines hard-negative sampling with uncertainty representations, while HedgeCode adds code--text relevance detection as auxiliary supervision~\citep{AAAIUA,HedgeCode}. CoCoHaNeRe incorporates hard negatives similar to the paired code, whereas R2PS draws candidates from a dual encoder's rankings to train a downstream cross-encoder~\citep{CoCoHaNeRe,R2PS}. \method{} differs by using the frozen initial retriever's query-specific full-corpus rankings to refine the retriever itself.
% 中文：负例感知目标改变对比学习中所使用的竞争候选。Soft-InfoNCE 根据估计的相关性对负例进行加权~\citep{SoftInfoNCE}。不确定性感知训练将困难负例采样与不确定性表示相结合，而 HedgeCode 则将代码—文本相关性检测作为辅助监督~\citep{AAAIUA,HedgeCode}。CoCoHaNeRe 纳入与配对代码相似的困难负例，而 R2PS 从双编码器的排序中提取候选，用于训练下游交叉编码器~\citep{CoCoHaNeRe,R2PS}。\method{} 的区别在于，它利用冻结初始检索器产生的逐查询全语料库排序来进一步细化检索器本身。

\subsection{Retriever Feedback and Refinement}

Hard-negative mining in dense text retrieval obtains targeted competitors from BM25 results, asynchronously refreshed ANN indices, static or dynamic retriever-mined pools, and denoised cross-batch negatives~\citep{DPR,ANCE,HardNegDR,RocketQA}. In our formulation, retriever feedback is offline and decoupled: the frozen initial retriever ranks the corpus once per query, and its high-ranked unpaired candidates form a fixed Failure Candidate Pool for subsequent failure-calibrated refinement.
% 中文：稠密文本检索中的困难负例挖掘从 BM25 结果、异步刷新的近似最近邻索引、静态或动态的检索器挖掘候选池，以及经过降噪的跨批次负例中获取更具针对性的竞争候选~\citep{DPR,ANCE,HardNegDR,RocketQA}。在本文的设计中，检索器反馈以离线且解耦的方式使用：冻结的初始检索器对每个查询执行一次全语料库排序，其中高排名的未配对候选构成固定的失败候选池（Failure Candidate Pool），用于后续的失败校准细化（failure-calibrated refinement）。

\subsection{Late Interaction and Reranking}

Fine-grained code-search methods use co-attention, cross-modal features, and relevance supervision to model local query--code correspondence~\citep{FcarCS,FineGrainedCS,HedgeCode}. Late interaction preserves token representations and aggregates token-wise similarities at scoring time; ColBERT's MaxSim is representative~\citep{ColBERT}. Building on late interaction, the reranking stage reorders the global retriever's top-\(K\) by fusing token-level MaxSim evidence with global scores.
% 中文：细粒度代码搜索方法利用协同注意力、跨模态特征和相关性监督，对查询与代码之间的局部对应关系进行建模~\citep{FcarCS,FineGrainedCS,HedgeCode}。后期交互保留词元级表示，并在评分阶段聚合逐词元相似度；ColBERT 的 MaxSim 是其中的代表性形式~\citep{ColBERT}。在后期交互的基础上，重排阶段通过融合词元级 MaxSim 证据与全局分数，对全局检索器返回的前 \(K\) 个候选重新排序。

\section{Method}
\label{sec:method}

In this section, we first formulate the code-search problem and introduce the score-margin notation used throughout (\hyperref[sec:problem_formulation]{Section~\ref*{sec:problem_formulation}}). As shown in Figure~\ref{fig:framework}, \method{} consists of three components: Failure Candidate Harvesting (\hyperref[sec:failure_harvesting]{Section~\ref*{sec:failure_harvesting}}), Failure-Calibrated Contrastive Refinement (\hyperref[sec:failure_refinement]{Section~\ref*{sec:failure_refinement}}), and Dual-Granularity Reranking (\hyperref[sec:reranking_method]{Section~\ref*{sec:reranking_method}}). The first two components transform the frozen initial retriever's query-specific full-corpus rankings into refinement supervision for \method{}-Global, while the third combines global scores with token-level MaxSim evidence to produce \method{}-Rerank.
% 中文：本节首先形式化代码搜索问题，并引入全文使用的分数间隔符号（第~\ref{sec:problem_formulation} 节）。如图~\ref{fig:framework} 所示，\method{} 包含三个组成部分：失败候选挖掘（第~\ref{sec:failure_harvesting} 节）、失败校准对比细化（第~\ref{sec:failure_refinement} 节）和双粒度重排（第~\ref{sec:reranking_method} 节）。前两个部分将冻结初始检索器产生的逐查询全语料库排序转化为 \method{}-Global 的细化监督，第三个部分则将全局分数与词元级 MaxSim 证据相结合，得到 \method{}-Rerank。

\subsection{Problem Formulation}
\label{sec:problem_formulation}

Let \(\mathcal{D}=\{(q_i,c_i^+)\}_{i=1}^{N}\) denote a code-search training set of \(N\) query--code pairs, where \(q_i\) is a natural-language query and \(c_i^+\) is its paired code snippet. A dual encoder with parameters \(\theta\) maps queries and code into a shared space through \(f_\theta\) and \(g_\theta\). Let \(f_\theta(q)\) and \(g_\theta(c)\) denote the resulting \(\ell_2\)-normalized sequence representations. Their global retrieval score is
% 中文：设 \(\mathcal{D}=\{(q_i,c_i^+)\}_{i=1}^{N}\) 表示包含 \(N\) 个查询—代码对的代码搜索训练集，其中 \(q_i\) 是自然语言查询，\(c_i^+\) 是与其配对的代码片段。参数为 \(\theta\) 的双编码器分别通过 \(f_\theta\) 和 \(g_\theta\) 将查询与代码映射到共享空间。令 \(f_\theta(q)\) 和 \(g_\theta(c)\) 表示所得的 \(\ell_2\) 归一化序列表示，其全局检索分数定义为
\begin{equation}
  s_\theta(q,c)=f_\theta(q)^{\top}g_\theta(c).
  \label{eq:global_score}
\end{equation}
Because both representations have unit norm, \(s_\theta\) is their cosine similarity, and candidates are ranked in descending order of this score.
% 中文：由于两个表示均具有单位范数，\(s_\theta\) 等于二者的余弦相似度，候选代码按照该分数从高到低排序。

Let \(\mathcal{C}\) denote the retrieval corpus. For any competing candidate \(c\in\mathcal{C}\setminus\{c_i^+\}\), define the score margin as
% 中文：令 \(\mathcal{C}\) 表示检索语料库。对于任意竞争候选 \(c\in\mathcal{C}\setminus\{c_i^+\}\)，其分数间隔定义为
\begin{equation}
  \mu_\theta(q_i,c)
  =s_\theta(q_i,c_i^+)-s_\theta(q_i,c).
  \label{eq:score_margin}
\end{equation}
A nonpositive margin means that \(c\) ties or outranks the paired code, whereas a positive margin is the score gap by which the paired code outranks \(c\). Candidates with nonpositive or small positive margins therefore lie at or near the observed ranking boundary, while large-margin candidates are already well separated.
% 中文：非正间隔表示候选 \(c\) 与配对代码同分或排在配对代码之前；正间隔则表示配对代码领先候选 \(c\) 的分数差。因此，间隔非正或具有较小正间隔的候选位于观测排序边界上或其附近，而具有较大间隔的候选已经与配对代码充分分离。

Let \(\mathbb{I}[\cdot]\) denote the indicator function. The rank of the paired code under \(s_\theta\) is
% 中文：令 \(\mathbb{I}[\cdot]\) 表示指示函数。配对代码在 \(s_\theta\) 下的排名可写为
\begin{equation}
  \operatorname{rank}_\theta(c_i^+\mid q_i)
  =1+\sum_{c\in\mathcal{C}\setminus\{c_i^+\}}
  \mathbb{I}\!\left[\mu_\theta(q_i,c)\leq 0\right],
  \label{eq:rank_margin}
\end{equation}
With the non-strict inequality, a tied candidate is counted before the paired code. The negative sets used to train the initial retriever are constructed without access to the final checkpoint's query-specific full-corpus rankings. \method{} uses these rankings as feedback to refine the comparisons that determine the paired code's observed ranks.
% 中文：由于这里采用非严格不等式，与配对代码同分的候选会被计在配对代码之前。初始检索器的负例集合在构造时无法使用最终检查点产生的逐查询全语料库排序。\method{} 将这些排序作为反馈，用于细化决定配对代码实际排名的分数比较。

Competitors are query dependent: a code snippet may rank low for one query yet highly for another. Refinement therefore associates each query with candidates from its own corpus ranking, preserving the link between observed scores and subsequent contrastive comparisons.
% 中文：竞争候选依赖于具体查询：同一代码片段在一个查询下可能排名较低，却可能在另一个查询下排名很高。因此，细化为每个查询关联其自身语料库排序中的候选，从而保留观测分数与后续对比比较之间的对应关系。

\subsection{Failure Candidate Harvesting}
\label{sec:failure_harvesting}

We first train an initial retriever with the underlying contrastive code-search objective and freeze its parameters \(\theta_0\). For every training query, the frozen model retrieves from the training code corpus. Let \(\mathcal{C}_{\mathrm{train}}\) denote the training code corpus, and let \(\mathcal{E}_i\) contain the paired code and all candidates sharing its URL. For a candidate set \(\mathcal{A}\), \(\operatorname{Top}_{L}^{s}(\mathcal{A})\) denotes its ordered subset of the \(L\) highest-scoring candidates under \(s\). Let \(M\) be the cached retrieval depth and \(m\), with \(1\leq m\leq M\), the retained depth used for refinement:
% 中文：我们首先使用基础对比式代码搜索目标训练初始检索器，并冻结其参数 \(\theta_0\)。对于每个训练查询，冻结模型在训练代码语料库中执行检索。令 \(\mathcal{C}_{\mathrm{train}}\) 表示训练代码语料库，令 \(\mathcal{E}_i\) 包含配对代码以及所有与其共享 URL 的候选。对于候选集合 \(\mathcal{A}\)，\(\operatorname{Top}_{L}^{s}(\mathcal{A})\) 表示其在评分函数 \(s\) 下得分最高的 \(L\) 个候选组成的有序子集。令 \(M\) 表示缓存的检索深度，令满足 \(1\leq m\leq M\) 的 \(m\) 表示实际保留并用于细化的深度：
\begin{equation}
  \begin{aligned}
    \mathcal{H}_i
    &=\operatorname{Top}_{M}^{s_{\theta_0}(q_i,\cdot)}
      (\mathcal{C}_{\mathrm{train}}\setminus\mathcal{E}_i), \\
    \mathcal{F}_i
    &=\operatorname{Top}_{m}^{s_{\theta_0}(q_i,\cdot)}(\mathcal{H}_i).
  \end{aligned}
  \label{eq:fc_pool}
\end{equation}

Thus, \(\mathcal{H}_i\) is the cached top-\(M\) candidate list and \(\mathcal{F}_i\) is its top-\(m\) \emph{Failure Candidate Pool}; the members of \(\mathcal{F}_i\) are \emph{Failure Candidates}. At each update, \(r\) candidates are sampled uniformly without replacement from the ranked positions in \(\mathcal{F}_i\), where \(1\leq r\leq m\). This fixes the number of added comparisons while concentrating refinement on the high-ranked unpaired competitors observed for \(q_i\).
% 中文：其中，\(\mathcal{H}_i\) 是缓存的前 \(M\) 个候选列表，\(\mathcal{F}_i\) 是其中排名最高的前 \(m\) 个候选，并构成查询 \(q_i\) 的\emph{失败候选池（Failure Candidate Pool）}；\(\mathcal{F}_i\) 中的元素称为\emph{失败候选（Failure Candidates）}。每次参数更新时，从 \(\mathcal{F}_i\) 的排名位置中均匀、无放回地采样 \(r\) 个候选，其中 \(1\leq r\leq m\)。这样可以在固定新增比较数量的同时，使细化过程聚焦于初始检索器为查询 \(q_i\) 找到的高排名未配对竞争候选。

Harvesting runs once with the frozen parameters \(\theta_0\). Pool membership and initial order consequently remain fixed while refinement updates \(\theta\), so the optimization uses a stable record of the initial retriever's ranking behavior without rerunning corpus retrieval after every update.
% 中文：候选挖掘仅使用冻结参数 \(\theta_0\) 执行一次。因此，在细化更新 \(\theta\) 的过程中，候选池成员及其初始次序保持不变；优化过程据此使用初始检索器排序行为的固定记录，而无须在每次更新后重新执行全语料库检索。

\subsection{Failure-Calibrated Contrastive Refinement}
\label{sec:failure_refinement}

Starting from \(\theta_0\), we retain the initial retriever's contrastive objective and add a contrastive softmax over the paired code and harvested competitors. For a minibatch index set \(\mathcal{B}\subseteq\{1,\ldots,N\}\), let \(\mathcal{L}_{\mathrm{base}}\) denote the initial retriever's batch-level contrastive objective. For each \(i\in\mathcal{B}\), let \(\mathcal{S}_i\subseteq\mathcal{F}_i\) contain the \(r\) candidates sampled for query \(q_i\), so that \(|\mathcal{S}_i|=r\), and let \(\tau_f>0\) denote the failure-candidate temperature. The per-query failure-candidate loss is
% 中文：以 \(\theta_0\) 为起点，我们保留初始检索器的对比目标，并在配对代码与挖掘得到的竞争候选上加入对比 softmax。对于小批量索引集合 \(\mathcal{B}\subseteq\{1,\ldots,N\}\)，令 \(\mathcal{L}_{\mathrm{base}}\) 表示初始检索器在该批次上的对比目标。对于每个 \(i\in\mathcal{B}\)，令 \(\mathcal{S}_i\subseteq\mathcal{F}_i\) 包含为查询 \(q_i\) 采样的 \(r\) 个候选，即 \(|\mathcal{S}_i|=r\)，并令 \(\tau_f>0\) 表示失败候选温度。逐查询的失败候选损失定义为
\begin{equation}
  \mathcal{L}_{\mathrm{FC}}^{i}
  =-\log
  \frac{\exp(s_\theta(q_i,c_i^+)/\tau_f)}
  {\begin{aligned}
     &\exp(s_\theta(q_i,c_i^+)/\tau_f) \\
     &\quad+\sum_{c\in\mathcal{S}_i}
       \exp(s_\theta(q_i,c)/\tau_f)
   \end{aligned}},
  \label{eq:fc_loss}
\end{equation}
With \(\lambda_f\geq 0\) controlling the contribution of the added objective, the complete refinement loss is
% 中文：令 \(\lambda_f\geq 0\) 控制新增目标在完整细化目标中的相对贡献，则完整的细化损失为
\begin{equation}
  \mathcal{L}_{\mathrm{ref}}
  =\mathcal{L}_{\mathrm{base}}
  +\frac{\lambda_f}{|\mathcal{B}|}
   \sum_{i\in\mathcal{B}}\mathcal{L}_{\mathrm{FC}}^{i}.
  \label{eq:refinement_loss}
\end{equation}

Equation~\ref{eq:refinement_loss} adds the batch average of the per-query losses \(\mathcal{L}_{\mathrm{FC}}^i\) without changing the definition of \(\mathcal{L}_{\mathrm{base}}\).
% 中文：式~\ref{eq:refinement_loss} 在不改变 \(\mathcal{L}_{\mathrm{base}}\) 定义的情况下，加入逐查询失败候选损失 \(\mathcal{L}_{\mathrm{FC}}^i\) 的批次平均值。

\paragraph{Score-margin interpretation.}
The added term admits a direct score-margin form,
% 中文：新增损失项可直接写成分数间隔形式：
\begin{equation}
  \mathcal{L}_{\mathrm{FC}}^{i}
  =\log\!\left(1+\sum_{c\in\mathcal{S}_i}
  \exp[-\mu_\theta(q_i,c)/\tau_f]\right).
  \label{eq:margin_loss}
\end{equation}
For candidates in the same sampled set, the gradient magnitude with respect to \(\mu_\theta(q_i,c)\) is proportional to \(\exp[-\mu_\theta(q_i,c)/\tau_f]\). Smaller or negative margins therefore receive greater optimization pressure, and \(\tau_f\) controls how sharply that pressure concentrates as the margin decreases. This margin-dependent weighting defines failure-calibrated refinement, whereas \(\lambda_f\) balances the aggregate FC objective against \(\mathcal{L}_{\mathrm{base}}\). Together, the two objectives refine the global retrieval space to produce \method{}-Global.
% 中文：对于同一采样集合中的候选，损失关于 \(\mu_\theta(q_i,c)\) 的梯度幅度与 \(\exp[-\mu_\theta(q_i,c)/\tau_f]\) 成正比。因此，间隔较小或为负的候选承受更强的优化压力，而 \(\tau_f\) 控制该压力随间隔减小而集中的程度。这种依赖分数间隔的加权构成失败校准细化；\(\lambda_f\) 则平衡整体 FC 目标与 \(\mathcal{L}_{\mathrm{base}}\) 的相对权重。两个目标共同细化全局检索空间，得到 \method{}-Global。

\subsection{Dual-Granularity Reranking}
\label{sec:reranking_method}

The rank-margin formulation above motivates concentrating additional comparison on high-scoring competitors. The same rank-focused principle carries into inference: \method{}-Global first retrieves candidates from the full corpus with sequence-level scores, and \method{}-Rerank then applies token-level MaxSim only to the resulting top-\(K\)~\citep{ColBERT}, where \(K\) is the reranking depth. The fused global and local scores determine the final order within this shortlist.
% 中文：上述分数间隔形式说明，应当将额外的比较集中于高分竞争候选。同一面向排名的原则也延伸到推理阶段：\method{}-Global 首先根据序列级分数从完整语料库中检索候选，\method{}-Rerank 随后仅对所得的前 \(K\) 个候选应用词元级 MaxSim~\citep{ColBERT}，其中 \(K\) 表示重排深度。融合后的全局分数与局部分数决定该候选列表内部的最终次序。

Let \(\{\mathbf{h}^{q}_{a}\}_{a=1}^{T_q}\) and \(\{\mathbf{h}^{c}_{b}\}_{b=1}^{T_c}\) be the contextual token representations produced by the refined query and code encoders, where \(T_q\) and \(T_c\) are the numbers of retained query and lexical code tokens, respectively. Padding and special tokens are excluded. Their local-interaction score is
% 中文：设 \(\{\mathbf{h}^{q}_{a}\}_{a=1}^{T_q}\) 和 \(\{\mathbf{h}^{c}_{b}\}_{b=1}^{T_c}\) 分别表示细化后的查询编码器和代码编码器产生的上下文词元表示，其中 \(T_q\) 和 \(T_c\) 分别是保留下来的有效查询词元与词法代码词元数量。填充词元和特殊词元均被排除。其局部交互分数定义为
\begin{equation}
  s_{\mathrm{loc}}(q,c)=\frac{1}{T_q}\sum_{a=1}^{T_q}
  \max_{1\leq b\leq T_c}
  \cos(\mathbf{h}^{q}_{a},\mathbf{h}^{c}_{b}).
  \label{eq:maxsim}
\end{equation}

For each query token, the maximum selects the code token with the highest cosine similarity; averaging these maxima aggregates the token-level matches while normalizing for query length.
% 中文：对于每个查询词元，最大值操作选出余弦相似度最高的代码词元；对这些最大值取平均，在聚合词元级匹配证据的同时对查询长度进行归一化。

Let \(\mathcal{R}_K(q)\) be the top-\(K\) list returned by \method{}-Global. Let \(\bar{s}_\theta(q)\) and \(\sigma_\theta(q)\) be the mean and population standard deviation of \(s_\theta(q,\cdot)\) over \(\mathcal{R}_K(q)\), and define \(\bar{s}_{\mathrm{loc}}(q)\) and \(\sigma_{\mathrm{loc}}(q)\) analogously for \(s_{\mathrm{loc}}(q,\cdot)\). We standardize the two scores as
% 中文：令 \(\mathcal{R}_K(q)\) 表示 \method{}-Global 为查询 \(q\) 返回的前 \(K\) 个候选列表。令 \(\bar{s}_\theta(q)\) 和 \(\sigma_\theta(q)\) 分别表示 \(s_\theta(q,\cdot)\) 在 \(\mathcal{R}_K(q)\) 上的均值与总体标准差；类似地，令 \(\bar{s}_{\mathrm{loc}}(q)\) 和 \(\sigma_{\mathrm{loc}}(q)\) 分别表示 \(s_{\mathrm{loc}}(q,\cdot)\) 的均值与总体标准差。两类分数分别标准化为
\begin{equation}
  \begin{aligned}
    \widetilde{s}_\theta(q,c)
    &=\frac{s_\theta(q,c)-\bar{s}_\theta(q)}
      {\sigma_\theta(q)+10^{-6}},\\
    \widetilde{s}_{\mathrm{loc}}(q,c)
    &=\frac{s_{\mathrm{loc}}(q,c)-\bar{s}_{\mathrm{loc}}(q)}
      {\sigma_{\mathrm{loc}}(q)+10^{-6}}.
  \end{aligned}
  \label{eq:score_standardization}
\end{equation}
The \(10^{-6}\) term prevents a zero denominator.
% 中文：其中，\(10^{-6}\) 用于避免标准差为零时出现零分母。
With \(\alpha\in[0,1]\), the final score is
% 中文：取 \(\alpha\in[0,1]\)，最终分数定义为
\begin{equation}
  s_{\mathrm{fuse}}(q,c)=\alpha\widetilde{s}_\theta(q,c)
  +(1-\alpha)\widetilde{s}_{\mathrm{loc}}(q,c).
  \label{eq:fusion}
\end{equation}
The fused score \(s_{\mathrm{fuse}}\) interpolates between token-level correspondence at \(\alpha=0\) and the \method{}-Global ordering at \(\alpha=1\); intermediate values combine sequence-level relevance from the refined dual encoder with query-token alignments from MaxSim to determine the final shortlist order.
% 中文：融合分数 \(s_{\mathrm{fuse}}\) 在两种排序信号之间进行插值：当 \(\alpha=0\) 时使用词元级对应关系，当 \(\alpha=1\) 时采用 \method{}-Global 排序；中间取值将细化双编码器提供的序列级相关性与 MaxSim 提供的查询—代码词元对齐相结合，从而确定候选列表的最终顺序。

Only candidates inside the top-\(K\) set are reordered; all remaining corpus items preserve their \method{}-Global order.
% 中文：只有前 \(K\) 集合内的候选会被重新排序，其余语料库条目保持 \method{}-Global 产生的顺序。

\section{Experiments}
\label{sec:experiments}

We evaluate \method{} under protocol-matched full-corpus retrieval across all six CodeSearchNet languages. Beyond overall retrieval effectiveness, we isolate the contributions of candidate mining, failure-calibrated refinement, and MaxSim reranking, and analyze performance by initial rank and encoder architecture together with the latency cost of reranking.
% 中文：我们在 CodeSearchNet 六种语言上采用协议一致的全语料库检索设置评估 \method{}。除整体检索效果外，我们还分别考察候选挖掘、失败校准细化和 MaxSim 重排的贡献，并分析不同初始排名区间和编码器架构下的表现，以及重排带来的延迟成本。

\subsection{Experimental Setup}
\label{sec:experimental_setup}

\paragraph{Dataset and metrics.}
CodeSearchNet~\citep{CodeSearchNet} contains natural-language--code pairs in Java, JavaScript, Ruby, Python, PHP, and Go. Each test query is ranked against the complete language-specific corpus. MRR is the primary metric; we additionally report Recall@1, Recall@5, and Recall@10 (R@1/R@5/R@10).
% 中文：CodeSearchNet~\citep{CodeSearchNet} 包含 Java、JavaScript、Ruby、Python、PHP 和 Go 六种语言的自然语言—代码配对。每个测试查询均在对应语言的完整语料库中进行排序。MRR 是主要指标；我们还报告 Recall@1、Recall@5 和 Recall@10（R@1/R@5/R@10）。

For a query \(q_i\), let \(r_i\) denote the rank of its paired code in the retrieved list. Its reciprocal rank is \(1/r_i\), and the language-level mean reciprocal rank is
\[
\mathrm{MRR}_{\ell}
=
\frac{1}{N_{\ell}}
\sum_{i=1}^{N_{\ell}}
\frac{1}{r_i},
\]
where \(N_{\ell}\) is the number of queries in language \(\ell\). We report macro MRR as the unweighted average of the six language-level MRR values:
\[
\mathrm{Macro\ MRR}
=
\frac{1}{6}
\sum_{\ell=1}^{6}
\mathrm{MRR}_{\ell}.
\]
All MRR and recall values are reported as percentages.
% 中文：对于查询 (q_i)，令 (r_i) 表示其配对代码在检索列表中的排名，则该查询的倒数排名为 (1/r_i)。语言 \(\ell\) 的平均倒数排名定义为上式，其中 (N_{\ell}) 表示该语言的查询数量。本文将六种语言级 MRR 进行等权平均，得到宏平均 MRR。所有 MRR 和召回率结果均以百分比表示。

\paragraph{Implementation details.}
Unless stated otherwise, Failure Candidate Harvesting retains \(M=32\) candidates per query, and refinement samples \(r=1\) candidate from the top \(m=8\) using \(\lambda_f=0.45\) and \(\tau_f=0.03\) for three epochs. The candidate-source controls use the same initial checkpoint, three-epoch schedule, and one-candidate-per-query budget, varying only among random, static, and retriever-mined candidates. Refinement uses global representations only; MaxSim is applied only when reranking the retrieved top-\(K\). Unrounded six-language validation macro MRR selects \(K=20\) and \(\alpha=0.5\), and the selected values and model checkpoints are fixed before test evaluation. We report 95\% confidence intervals from 10,000 language-stratified paired bootstrap samples; these intervals measure test-query sampling uncertainty for fixed checkpoints rather than variation across training runs. Appendix~\ref{app:experimental_details} provides complete optimization, candidate-construction, and encoder-specific settings; Appendix~\ref{app:statistical_reliability} provides the statistical procedure.

\subsection{Overall Retrieval Effectiveness}
\label{sec:main_results}

Under the shared full-corpus evaluation across six languages, \method{}-Global raises the initial retriever's macro MRR from 79.8 to 80.6. Adding validation-selected MaxSim reranking further raises it to 81.1. Both variants improve in all six languages: the language-level gains range from 0.6 to 1.2 points for \method{}-Global and from 1.0 to 1.7 points for \method{}-Rerank. The gains are consistent across languages rather than concentrated in a single corpus.
% 中文：在六种语言的统一全语料库评测中，\method{}-Global 将初始检索器的宏平均 MRR 从 79.8 提升至 80.6；在此基础上加入验证集选定的 MaxSim 重排后，\method{}-Rerank 达到 81.1。两种变体都在六种语言上取得提升：\method{}-Global 的逐语言增益为 0.6--1.2 个百分点，\method{}-Rerank 的增益为 1.0--1.7 个百分点。六种语言的结果呈现出一致的提升趋势，宏平均增益也没有集中在单一语料库上。

The improvements are concentrated near the top of the ranked list. From the initial retriever to \method{}-Global and \method{}-Rerank, R@1 increases from 70.7 to 71.9 and 72.6, and R@5 from 91.3 to 91.5 and 91.7; R@10 remains around 95.1. \method{} therefore has its clearest effect on the relative ordering of the first few candidates, while the overall coverage of the top ten changes little.
% 中文：改进主要发生在排序列表的顶部。从初始检索器到 \method{}-Global 和 \method{}-Rerank，R@1 分别从 70.7 提升至 71.9 和 72.6，R@5 从 91.3 提升至 91.5 和 91.7；R@10 则保持在约 95.1。\method{} 对前几名候选的相对次序影响更明显，而前十名整体的覆盖率变化较小。

Stratifying queries by the paired code's initial rank makes this pattern more explicit. Among the 13,261 queries whose paired code starts at ranks 2--10, conditional MRR increases by 8.9 points with \method{}-Global and by 11.3 points with \method{}-Rerank. Queries starting at ranks 11--50 or below also improve, but by smaller margins. \method{} is most effective when the paired code is already close to the top yet remains behind a small number of high-scoring candidates. The initial retriever's full-corpus ranking supplies a concrete competition signal for these queries, and refinement uses that signal to update the subsequent retrieval representation.
% 中文：按初始排名进一步划分后，这一变化更加集中。在配对代码初始排名为 2--10 的 13,261 个查询中，\method{}-Global 和 \method{}-Rerank 的条件 MRR 分别提高 8.9 和 11.3 个百分点；初始排名为 11--50 或更低的查询也有提升，但幅度明显较小。\method{} 对已经接近排序顶部、但仍被少量高分候选压在前面的配对代码最为有效。初始检索器的全语料库排名为这类查询提供了具体的竞争信号，细化阶段则利用这些信号调整后续检索表示。

The rank changes provide a more detailed view of this improvement. Relative to the initial retriever, \method{}-Rerank moves 2,644 paired codes that were not initially at rank 1 into the top position, while 1,624 initially rank-1 paired codes leave the first position, yielding a net gain of 1,020 rank-1 retrievals. This pattern is consistent with the largest conditional gains occurring in the initial-rank 2--10 group.
% 中文：排名变化进一步细化了这一改进。相较初始检索器，\method{}-Rerank 将 2,644 个原本未处于首位的配对代码提升至 rank 1，同时有 1,624 个原本位于 rank 1 的配对代码离开首位，最终净增加 1,020 个 rank-1 检索结果。这一变化与初始排名 2--10 区间出现最大条件收益的结果一致。

\subsection{Controlled Analysis of \method{}}
\label{sec:component_analysis}

\paragraph{Refinement and reranking contribute complementary gains.}
Table~\ref{tab:ablation} compares refinement and reranking under the same configuration. Applying MaxSim to the initial retriever raises macro MRR from 79.8 to 80.4; failure-calibrated refinement alone reaches 80.6; and combining the two stages gives \method{}-Rerank an MRR of 81.1. Refinement first changes the global retrieval representation, after which MaxSim compares token-level evidence within the candidate set. The former expands the paired code's advantage in the global ranking, while the latter adjusts the ordering of candidates that have already reached the shortlist. The paired-bootstrap 95\% confidence intervals are [0.7, 1.0] for \method{}-Global and [1.1, 1.5] for \method{}-Rerank, both relative to the initial retriever.
% 中文：表~\ref{tab:ablation} 在同一配置下比较细化和重排的作用。仅对初始检索器使用 MaxSim 时，宏平均 MRR 从 79.8 提升至 80.4；只进行失败校准细化时，MRR 达到 80.6；两个阶段结合后，\method{}-Rerank 达到 81.1。细化首先改变全局检索表示，MaxSim 随后在候选内部重新比较词元级证据。前一阶段扩大了配对代码在全局排序中的优势，后一阶段则进一步调整了已经进入候选集合的代码顺序。相对于初始检索器，\method{}-Global 和 \method{}-Rerank 的配对 bootstrap 95\% 置信区间分别为 [0.7, 1.0] 和 [1.1, 1.5]。

\paragraph{Candidate source determines whether refinement helps.}
\label{sec:candidate_controls}

Table~\ref{tab:candidate_controls} varies only the source of one added candidate per query. With the training schedule fixed, random and static candidates change macro MRR by \(-0.05\) and \(-0.10\) points relative to the 79.77 MRR no-refinement setting, whereas the Failure Candidate mined by the initial retriever adds \(0.35\) points and raises R@1 by \(0.83\) points. Under the matched schedule and candidate budget, positive gains appear only when the candidate corresponds to the current retriever's ranking state. Full-corpus rankings provide query-specific competition signals, which refinement then uses to strengthen the candidate relations that affect the current order.
% 中文：表~\ref{tab:candidate_controls} 展示了候选来源对细化结果的影响。在每个查询只增加一个候选、并保持训练日程不变的情况下，随机候选和静态候选相对于 MRR 为 79.77 的无细化设置，分别使宏平均 MRR 变化 \(-0.05\) 和 \(-0.10\) 个百分点；由初始检索器挖掘的 Failure Candidate 则带来 \(0.35\) 个百分点的提升，并使 R@1 增加 \(0.83\) 个百分点。相同的候选预算只有在候选与当前检索器的排序状态相匹配时才带来收益。这一对照凸显了候选来源的重要性：全语料库排名提供了逐查询的竞争信息，细化阶段据此强化真正影响当前排序的候选关系。

\paragraph{Refinement is stable across the evaluated parameter range.}
Table~\ref{tab:training_sensitivity} reports one-factor sensitivity around the primary \((\lambda_f,m)=(0.45,8)\) configuration. All three values of \(\lambda_f\) obtain a macro MRR of 80.6; for \(m=2,8,32\), MRR is 80.4, 80.6, and 80.5, respectively. The largest difference across the evaluated settings is 0.2 points. The main gain therefore persists across the tested training range rather than depending on a single precise parameter choice.
% 中文：围绕主要配置 \((\lambda_f,m)=(0.45,8)\) 的敏感性结果见表~\ref{tab:training_sensitivity}。三个 \(\lambda_f\) 取值均得到 80.6 的宏平均 MRR；当 \(m=2,8,32\) 时，MRR 分别为 80.4、80.6 和 80.5，所有设置之间的最大差异只有 0.2 个百分点。主要收益并不依赖某一个精确的参数组合，失败校准细化在所测试的训练范围内都能维持相近效果。

\subsection{Reranking Gains Across Encoder Architectures}
\label{sec:encoder_compatibility}

To test whether reranking depends on a particular encoder representation, we apply the same harvesting, refinement, and MaxSim pipeline to CoCoSoDa, UniXcoder~\citep{UniXcoder}, and the data-flow-aware GraphCodeBERT~\citep{GraphCodeBERT}. For each encoder, Global and Rerank use the same refined checkpoint, so the comparison changes only the MaxSim stage. Macro MRR rises from 80.1 to 80.6, from 76.0 to 76.6, and from 72.8 to 74.0, respectively.
% 中文：为了检验重排阶段是否依赖特定的编码器表示，我们将相同的候选挖掘、细化和 MaxSim 流程应用于 CoCoSoDa、UniXcoder~\citep{UniXcoder} 和 GraphCodeBERT~\citep{GraphCodeBERT}。对于每个编码器，Global 与 Rerank 使用同一个细化检查点，唯一变化是是否加入 MaxSim。宏平均 MRR 分别从 80.1 提升至 80.6、从 76.0 提升至 76.6，以及从 72.8 提升至 74.0。

The gains are 0.5, 0.7, and 1.2 points for CoCoSoDa, UniXcoder, and GraphCodeBERT, respectively, and all six languages improve under each encoder. The global encoder establishes the overall candidate ordering, while MaxSim adds token-level matching evidence within that ordering; this combination remains effective for contrastive, unified code, and data-flow-aware representations. GraphCodeBERT obtains the largest gain, 1.2 points, consistent with a complementary relationship between structure-aware global representations and local token-level reranking.
% 中文：增益幅度分别为 0.5、0.7 和 1.2 个百分点，并且三种编码器的六种语言都获得正向 MRR 变化。全局编码器负责建立候选的整体排序，MaxSim 则在这一排序基础上补充词元级匹配证据；这一组合在对比式表示、统一代码表示和数据流感知表示上都有效。GraphCodeBERT 上的增益最大，为 1.2 个百分点，与结构感知的全局表示和局部词元级重排之间的互补关系相一致。

\subsection{Reranking Effectiveness and Efficiency}
\label{sec:efficiency}

Validation MRR selects the fusion setting, and Figure~\ref{fig:reranking_sensitivity} traces the resulting effectiveness--latency trade-off on held-out queries. At \(K=20\), MaxSim alone (\(\alpha=0\)) obtains 81.2 validation MRR, global retrieval alone (\(\alpha=1\)) obtains 81.9, and equal-weight fusion reaches 82.2. Global retrieval establishes the candidate range, while MaxSim uses token-level correspondences to order candidates within that range; combining the two scores gives the highest validation MRR.
% 中文：验证集上的融合结果用于确定配置，图~\ref{fig:reranking_sensitivity} 则展示了该配置在留出查询上的效果--延迟权衡。当 \(K=20\) 时，仅使用 MaxSim（\(\alpha=0\)）的验证集 MRR 为 81.2，仅使用全局检索分数（\(\alpha=1\)）为 81.9，而等权融合达到 82.2。全局检索确定候选范围，MaxSim 则利用候选内部的词元级对应关系进行进一步排序；两种分数结合后取得了最高的验证集 MRR。

With \(\alpha=0.5\) fixed, the selected \(K=20\) setting reaches 81.1 test MRR at 26.0 ms per JavaScript query. \(K=10\) reaches 81.0 MRR at 19.0 ms, while \(K=50\) and \(K=100\) remain at 81.0 and raise latency to 46.6 and 85.2 ms. Across the evaluated depths, test MRR varies by 0.1 points while latency increases from 19.0 to 85.2 ms. Within the evaluated range, enlarging the candidate depth yields diminishing ranking returns while online cost continues to rise.
% 中文：固定 \(\alpha=0.5\) 后，验证集选定的 \(K=20\) 配置在测试集上达到 81.1 MRR，单个 JavaScript 查询的在线延迟为 26.0 毫秒。将候选深度降至 \(K=10\) 后，MRR 降至 81.0，延迟为 19.0 毫秒；扩大到 \(K=50\) 和 \(K=100\) 时，MRR 仍为 81.0，但延迟分别升至 46.6 和 85.2 毫秒。在当前评测范围内，扩大候选深度带来的排序收益已趋于饱和，而在线计算开销仍会随之增加。

\section{Conclusion}
\label{sec:conclusion}

We presented \method{}, which uses the full-corpus rankings of an initial dual encoder to target refinement at the high-scoring competitors that determine retrieval order. Failure Candidate Harvesting and Failure-Calibrated Contrastive Refinement convert these rankings into query-specific supervision, producing \method{}-Global; \method{}-Rerank further incorporates token-level MaxSim evidence within the retrieved top-\(K\). Under a matched six-language CodeSearchNet protocol, \method{}-Global raises macro MRR from 79.8 to 80.6, and \method{}-Rerank reaches 81.1. Budget-matched controls favor retriever-harvested candidates over random and static alternatives, with the largest gains concentrated on queries whose paired code initially ranks 2--10. Retriever feedback targets near-top code-search misrankings.
% 中文：本文提出 \method{}，利用初始双编码器的全语料库排序，针对决定检索次序的高分竞争候选开展细化。失败候选挖掘与失败校准对比细化将这些排序转化为逐查询监督，得到 \method{}-Global；\method{}-Rerank 则在检索得到的前 \(K\) 个候选内进一步融合词元级 MaxSim 证据。在六语言 CodeSearchNet 的协议一致评测中，\method{}-Global 将宏平均 MRR 从 79.8 提升至 80.6，\method{}-Rerank 达到 81.1。预算匹配的对照结果支持检索器挖掘候选优于随机和静态替代方案，且最大收益集中在配对代码初始排名第 2--10 位的查询上。检索器反馈针对顶部附近的代码搜索排序错误。

\newpage
\section*{Limitations}

\method{} has three main limitations. First, refinement supervision is derived from a fixed full-corpus ranking, so each Failure Candidate Pool reflects the initial retriever rather than later refinement states. Future work can examine when selective pool refresh is beneficial. Second, the current evaluation covers the six-language CodeSearchNet benchmark, whose single-pair annotation also defines candidate supervision. High-ranked unpaired candidates may therefore include valid alternative implementations; multi-positive or semantic-equivalence supervision could distinguish these cases. The reported bootstrap intervals characterize test-query uncertainty for fixed checkpoints, while repeated runs are required to estimate training variability. Third, \method{}-Rerank can reorder only the top-\(K\) candidates returned by \method{}-Global. Increasing \(K\) expands this set but raises token-level rescoring latency, motivating further study of adaptive depths and more efficient late-interaction scoring.
% 中文：\method{} 主要有三点局限。首先，细化监督来自一次固定的全语料库排序，因此每个失败候选池反映的是初始检索器，而不是后续细化状态。未来可以研究在什么条件下选择性刷新候选池能够带来收益。其次，当前评测覆盖六语言 CodeSearchNet 基准，而该基准的单配对标注也决定了候选监督。高排名未配对候选因此可能包含有效的替代实现；多正例或语义等价监督可以进一步区分这些情况。当前 bootstrap 区间衡量固定检查点下的测试查询不确定性，而估计训练波动仍需要重复运行。第三，\method{}-Rerank 只能重新排列 \method{}-Global 返回的前 \(K\) 个候选。增大 \(K\) 可以扩大这一集合，但也会增加词元级重新计分延迟，这促使未来进一步研究自适应深度和更高效的后期交互计分。

\section{Fixed-Checkpoint Statistical Uncertainty}
\label{app:statistical_reliability}

We estimate 95\% confidence intervals for paired MRR differences using 10,000 repetitions of a language-stratified paired bootstrap. Within each language, test queries are resampled with replacement, and each sampled query contributes the reciprocal-rank difference between the same two systems. The six language-level differences are then macro-averaged. We compute intervals only for \method{}-Global and \method{}-Rerank against the protocol-matched initial retriever, excluding cited prior-work results. Table~\ref{tab:bootstrap} reports the aggregate and language-level intervals. Holding the trained checkpoints fixed makes these intervals a measure of finite-query sampling uncertainty.
% 中文：我们采用按语言分层的配对 bootstrap 进行 10,000 次重复采样，为 MRR 配对差值估计 95\% 置信区间。在每种语言内部，对测试查询进行有放回重采样，每个被采样查询贡献同一对系统之间的倒数排名差；随后对六种语言的差值进行宏平均。置信区间仅用于比较 \method{}-Global、\method{}-Rerank 与协议一致的初始检索器，不包含引用的既有工作结果。表~\ref{tab:bootstrap} 报告总体和逐语言区间。由于 bootstrap 保持训练检查点不变，这些区间衡量有限测试样本带来的不确定性，而不是不同独立训练运行之间的变化。
