\title{\method{}: Learning from Retriever-Induced Confusions for Code Search}

% Keep the submission anonymous while using the review option.
\author{Anonymous ACL submission}

\begin{document}
\maketitle

\begin{abstract}
Neural code search systems commonly optimize static hard negatives that need not match the high-ranked confusions produced at inference time. We propose \method{}, a failure-calibrated refinement framework that mines high-ranked non-ground-truth candidates from a frozen source retriever and uses them as targeted contrastive supervision. \method{} first refines global query--code representations and then applies a parameter-free token-level MaxSim reranker only to the top-\(K\) candidates. Under a matched local protocol on the six-language CodeSearchNet benchmark, refinement raises macro MRR from 79.77 to 80.57, and final reranking reaches 81.06, a 1.29-point improvement over the source retriever with a query-level 95\% bootstrap confidence interval of [1.11, 1.47]. Candidate-source controls and rank-stratified diagnostics show that the gains concentrate on initially mis-ranked queries, while also revealing regressions for some source top-1 cases.
% 中文：神经代码检索系统通常使用静态困难负样本进行优化，但这些负样本未必对应模型在推理时实际产生的高排名混淆候选。本文提出 \method{}，一种失败校准的细化框架：它从冻结的源检索器中挖掘高排名非标注候选，并将其作为有针对性的对比监督。\method{} 首先细化全局查询—代码表示，随后仅对前 \(K\) 个候选应用无参数的词元级 MaxSim 重排器。在六语言 CodeSearchNet 基准上的协议一致本地评测中，全局细化将宏平均 MRR 从 79.77 提升到 80.57，最终重排达到 81.06；相比源检索器提高 1.29 个点，查询级 95\% bootstrap 置信区间为 [1.11, 1.47]。候选来源对照和分层排名诊断表明，收益主要集中在初始排序错误的查询上，同时也揭示了部分源模型首位样本发生回退。
\end{abstract}

\section{Experiments}
\label{sec:experiments}

We evaluate three claims: (1) whether refinement with candidates retrieved by the source model improves code search; (2) whether the gain is specific to the candidate source rather than to an additional training stage; and (3) where the gain occurs in the ranked list and what inference cost it incurs. We organize the experiments around these claims instead of treating each implementation component as an independent contribution.
% 中文：我们围绕三个主张展开实验：（1）使用源检索器自身检索到的候选进行细化，能否提升代码检索；（2）性能增益是否确实来自候选来源，而不只是增加了一个训练阶段；（3）增益发生在排序列表的哪些位置，以及需要多少推理开销。实验据此组织，而不是把每个实现模块都当作独立贡献。

\subsection{Experimental Setup}
\label{sec:experimental_setup}

\paragraph{Dataset and metrics.}
We use the standard six-language CodeSearchNet benchmark~\citep{CodeSearchNet}, which contains natural-language queries paired with code in Java, JavaScript, Ruby, Python, PHP, and Go. Table~\ref{tab:dataset_stats} reports the frozen train, validation, and test splits. For each test query, a system ranks the corresponding language-specific codebase. Mean Reciprocal Rank (MRR) is the primary metric because our method targets the order of highly ranked candidates; we additionally report Recall at ranks 1, 5, and 10 (R@1/R@5/R@10). All values are percentages.
% 中文：我们采用标准的六语言 CodeSearchNet 基准，其中自然语言查询分别与 Java、JavaScript、Ruby、Python、PHP 和 Go 代码配对。表~\ref{tab:dataset_stats} 给出了固定的训练集、验证集和测试集划分。对于每个测试查询，系统在相应语言的代码库中进行排序。由于本文方法关注高排名候选之间的次序，我们将平均倒数排名（MRR）作为主要指标，同时报告排名 1、5 和 10 处的召回率（R@1/R@5/R@10）。所有数值均为百分比。

\paragraph{Source retriever and comparison protocol.}
Unless otherwise stated, the source retriever is CoCoSoDa~\citep{CoCoSoDa} trained with UA-HN~\citep{AAAIUA}. The source retriever, \method{}-Global, and \method{} with reranking are evaluated locally with the same data, codebase, and evaluation script. Values copied from prior papers are marked as reported and are included only to situate the local results; we do not compute paired differences or significance claims against those rows. We compare candidate sources under an equal budget of one additional candidate per query: a uniformly sampled non-positive (Random), a fixed pre-mined hard negative (Static), and a high-ranked non-ground-truth candidate retrieved by the frozen source model (FC).
% 中文：除非另有说明，源检索器采用使用 UA-HN 训练的 CoCoSoDa。源检索器、\method{}-Global 以及带重排的 \method{} 均使用相同的数据、候选代码库和评测脚本在本地评估。从既有论文复制的数值会被明确标记为“已报告”，仅用于说明本地结果在领域中的位置；我们不会针对这些行计算配对差值或提出显著性结论。为了公平比较候选来源，我们为每个查询统一加入一个额外候选：随机采样的非正例（Random）、固定的预挖掘困难负例（Static），以及由冻结源模型检索得到的高排名非标注候选（FC）。

\paragraph{Training and model selection.}
The source retriever is trained for 10 epochs with batch size 128, learning rate \(8\times10^{-6}\), and temperature 0.03. To construct FC supervision, we freeze the source checkpoint, retrieve over the training codebase, remove the paired code and candidates with the same URL, and store the top 32 remaining candidates. Refinement retains the first eight candidates and samples one per update. We train for three epochs with batch size 128, learning rate \(5\times10^{-6}\), FC weight 0.45, and FC temperature 0.03. The final refinement objective contains no CTRD or token-level local-interaction training loss.
% 中文：源检索器训练 10 个 epoch，批量大小为 128，学习率为 \(8\times10^{-6}\)，温度为 0.03。构造 FC 监督时，我们冻结源检索器，在训练代码库上执行检索，排除配对代码以及 URL 相同的候选，并保存排名最高的 32 个剩余候选。细化训练保留前 8 个候选，每次更新采样其中 1 个。细化阶段训练 3 个 epoch，批量大小为 128，学习率为 \(5\times10^{-6}\)，FC 权重为 0.45，FC 温度为 0.03。最终细化目标不包含 CTRD，也不包含词元级局部交互训练损失。

At inference time, \method{}-Global remains a dual encoder. The optional reranker computes a parameter-free token-level MaxSim score only for the global top-\(K\) candidates and combines the query-wise standardized global and local scores. We select \(K=20\) and fusion weight \(\alpha=0.5\) using six-language validation macro MRR and freeze both values before test evaluation. Checkpoints are also selected on validation data. All reported local results use the fixed training seed 123456 on one NVIDIA H20 GPU.
% 中文：在推理阶段，\method{}-Global 仍然是双编码器。可选重排器只对全局检索得到的前 \(K\) 个候选计算无需训练参数的词元级 MaxSim 分数，再融合按查询标准化后的全局分数与局部分数。我们依据六种语言验证集上的宏平均 MRR 选择 \(K=20\) 和融合权重 \(\alpha=0.5\)，并在测试前冻结这两个取值。模型检查点同样仅根据验证集选择。所有本地结果均使用固定训练种子 123456，并在一张 NVIDIA H20 GPU 上运行。

\paragraph{Uncertainty estimates.}
We use a stratified paired bootstrap over test queries to characterize query-sampling uncertainty in the difference between each refined system and its source. These intervals condition on the single trained checkpoint and therefore do not measure variation across training seeds.
% 中文：我们在测试查询上采用分层配对 bootstrap，刻画细化系统与源检索器之间差值的查询采样不确定性。这些区间以单个已训练检查点为条件，因此不能衡量不同训练种子带来的波动。

Following the compact single-table presentation of UA-HN~\citep{AAAIUA}, Table~\ref{tab:main_results} places published CodeSearchNet results and our matched local evaluation in one table. Rows marked with \reported{} are copied from the cited papers and provide field context only; rows marked with \localrun{} use the same local data, candidate codebase, evaluation script, and seed. All controlled improvement claims compare only the locally evaluated rows below the divider.
% 中文：参照 UA-HN~\citep{AAAIUA} 的紧凑单表形式，表~\ref{tab:main_results} 将 CodeSearchNet 上已发表的结果与本文协议一致的本地评测放在同一张表中。标记为 \reported{} 的行取自所引用的论文，只用于说明领域背景；标记为 \localrun{} 的行使用相同的本地数据、候选代码库、评测脚本和随机种子。本文所有受控增益结论都只比较分隔线下方的本地评测结果。

\subsection{Main Results}
\label{sec:main_results}

Table~\ref{tab:main_results} presents the main MRR results in the language order used by UA-HN. Under the matched local protocol, failure-candidate refinement improves average MRR from 79.77 to 80.57, an absolute gain of 0.80 points, and improves every language. Applying the validation-selected parameter-free reranker further raises average MRR to 81.06, corresponding to gains of 0.48 points over \method{}-Global and 1.29 points over the source retriever.
% 中文：表~\ref{tab:main_results} 按照 UA-HN 使用的语言顺序展示主要 MRR 结果。在协议一致的本地评测下，失败候选细化将平均 MRR 从 79.77 提升到 80.57，绝对提高 0.80 个点，并在六种语言上均有提升。进一步应用由验证集选择的无参数重排器后，平均 MRR 达到 81.06，相比 \method{}-Global 提升 0.48 个点，相比源检索器提升 1.29 个点。

The recall results clarify the type of improvement. From the source to the final reranked system, R@1 increases from 70.72 to 72.64, whereas R@5 changes from 91.28 to 91.68 and R@10 from 95.10 to 95.11. The gain is therefore concentrated in ordering already retrieved candidates near the top rather than expanding broad top-10 coverage. This pattern matches the intended role of failure-candidate refinement and shallow top-\(K\) reranking.
% 中文：召回率结果进一步说明了性能提升的性质。从源检索器到最终重排系统，R@1 从 70.72 提升到 72.64，而 R@5 仅从 91.28 变为 91.68，R@10 从 95.10 变为 95.11。因此，增益主要来自把已经检索到的候选更准确地排到前列，而不是扩大整体的前 10 名覆盖率。这与失败候选细化及浅层前 \(K\) 重排的预期作用一致。

The locally reproduced source is the appropriate point of comparison because it shares the full training and evaluation pipeline with \method{}. The upper block of Table~\ref{tab:main_results} provides published context, whereas only the lower, locally evaluated block supports controlled improvement claims; differences from the reported rows do not by themselves establish a state-of-the-art result.

\subsection{Does the Candidate Source Matter?}
\label{sec:candidate_controls}

Table~\ref{tab:candidate_controls} controls the number of added candidates and changes only how the candidate is obtained. Neither another training stage with Random candidates nor refinement with Static hard negatives improves the source. In contrast, a single source-retrieved candidate raises macro MRR by 0.35 points and R@1 by 0.83 points. This matched comparison supports the narrower claim that candidates from the trained retriever's own ranking neighborhood provide a more targeted refinement signal than the two proxy sources tested here.
% 中文：表~\ref{tab:candidate_controls} 固定额外候选的数量，只改变候选的获取方式。无论是使用 Random 候选再训练一个阶段，还是使用 Static 困难负例进行细化，都没有提升源检索器；相反，每个查询只使用一个由源检索器取得的候选，就使宏平均 MRR 提升 0.35 个点、R@1 提升 0.83 个点。这一匹配对比支持一个更克制的结论：与本文测试的两种代理候选来源相比，训练完成的检索器自身排序邻域能够提供更有针对性的细化信号。

\subsection{Where Does the Improvement Occur?}
\label{sec:rank_analysis}

We stratify all 52,561 test queries by the source rank of the labeled code. Table~\ref{tab:rank_strata} shows that the largest gains occur when the source places the labeled code at ranks 2--10: \method{}-Global improves MRR by 8.89 points in this stratum, and reranking increases the gain to 11.32 points. Gains are smaller but positive at ranks 11--50 and beyond 50. These results localize the aggregate improvement to the high-ranked neighborhood targeted by the method.
% 中文：我们按照标注代码在源检索器中的排名，对全部 52,561 个测试查询进行分层。表~\ref{tab:rank_strata} 显示，当源检索器把标注代码排在第 2--10 位时，增益最大：在这一层中，\method{}-Global 将 MRR 提升 8.89 个点，加入重排后增益扩大到 11.32 个点。在第 11--50 位和 50 位以后，增益较小但仍为正。这表明总体提升主要来自本文方法所针对的高排名邻域。

The same analysis also reveals regressions that an aggregate score would hide. Relative to the source, final reranking improves the labeled-code rank for 7,121 queries and worsens it for 5,741; it repairs 2,644 non-top-1 cases to rank 1 but moves 1,624 source top-1 cases downward. \subsection{Effectiveness--Efficiency Trade-off}
\label{sec:efficiency}

Table~\ref{tab:efficiency} varies only the reranking depth while keeping \(\alpha=0.5\), which is selected on validation data. \(K=20\) obtains the best validation-selected test MRR of 81.06 at 26.04 ms per JavaScript query and 3,063 MiB peak GPU memory. Increasing the depth to 50 or 100 does not improve MRR but raises total latency to 46.64 and 85.19 ms, respectively. \(K=10\) is a lower-cost alternative, reaching 81.03 MRR at 19.04 ms per query.

\subsection{Data and Protocol Audit}
\label{sec:audit}

We audit split isolation, candidate caches, checkpoint lineage, model selection, and test invocation. Across 121 checks, 115 pass and none fail critically. Exact URL, repository, and normalized code overlap between train, validation, and test are zero; validation and test gold-code coverage is 100\%. Each FC cache contains 32 unique, in-range, training-only candidates per query and excludes the paired example and same-URL code. Recomputing model selection from validation results independently recovers \(K=20,\alpha=0.5\).
% 中文：我们审计了数据划分隔离、候选缓存、检查点来源、模型选择和测试调用。在 121 项检查中，115 项通过，没有关键失败。训练集、验证集和测试集之间的 URL、代码仓库及规范化代码的精确重叠均为零，验证集和测试集标注代码的覆盖率为 100\%。每个 FC 缓存对每个查询都包含 32 个唯一、索引有效且仅来自训练集的候选，并排除了配对样本和 URL 相同的代码。根据验证结果独立重新执行模型选择，也得到 \(K=20,\alpha=0.5\)。

The six warnings correspond to natural-language strings duplicated in the frozen upstream benchmark splits. We retain and disclose these cases rather than modifying the benchmark after observing the data. This audit establishes the integrity and provenance of the executed pipeline, but it does not establish that every non-ground-truth candidate is semantically irrelevant.
% 中文：六条警告来自冻结的上游基准划分中重复出现的自然语言文本。我们保留并披露这些样本，而不是在观察数据后修改基准。该审计能够说明实际执行流程的数据完整性和来源可追溯性，但不能证明每个非标注候选在语义上都不相关。

\subsection{Scope of the Evidence}
\label{sec:scope}

Our conclusions are deliberately limited to the audited fixed-seed pipeline. Query-level bootstrap intervals do not replace multiple independent training runs, and the present results do not establish training-seed stability. Moreover, the final no-CTRD/no-local-training configuration has not yet been fully evaluated against a matched source checkpoint on multiple backbone families. We therefore claim improvement over the reproduced UA-HN source retriever, not universal backbone independence.
% 中文：本文结论被有意限定在已经审计的固定种子流程内。查询级 bootstrap 区间不能替代多个独立训练实验，当前结果也不能证明训练种子稳定性。此外，最终的无 CTRD、无局部交互训练配置尚未在多个骨干模型上与协议匹配的源检查点进行完整比较。因此，我们主张的是相对于本地复现 UA-HN 源检索器的提升，而不是已经证明了对任意骨干模型都有效。

Finally, CodeSearchNet provides one labeled code snippet per query, so a high-ranked non-ground-truth candidate may be a valid alternative implementation. Our method uses these candidates as challenging contrastive supervision without asserting that they are genuine semantic errors. A double-annotated candidate study would be needed to quantify alternative positives and fine-grained mismatch categories.
% 中文：最后，CodeSearchNet 每个查询只提供一个标注代码，因此高排名的非标注候选可能是有效的替代实现。本文仅把这些候选当作具有挑战性的对比监督，并不声称它们一定是真实的语义错误。若要量化替代正例以及细粒度语义不匹配类别，还需要开展双人标注的候选分析。

\section*{Limitations}

Our evidence is limited to CodeSearchNet, one audited training seed, and a source retriever based on CoCoSoDa with UA-HN. Query-level bootstrap intervals quantify evaluation-set uncertainty but do not establish stability across independent training runs. CodeSearchNet also provides only one labeled code snippet per query, so some high-ranked non-ground-truth candidates may be valid alternative implementations. Finally, the parameter-free reranker adds latency over global retrieval, and the current transfer evidence is insufficient to claim backbone independence.
% 中文：当前证据仅覆盖 CodeSearchNet、一个经过审计的训练随机种子，以及基于 CoCoSoDa 与 UA-HN 的源检索器。查询级 bootstrap 区间能够刻画评测集不确定性，但不能证明不同独立训练之间的稳定性。CodeSearchNet 每个查询只提供一个标注代码，因此部分高排名非标注候选可能是有效的替代实现。此外，无参数重排器会在全局检索之上增加延迟，现有迁移证据也不足以支持骨干模型无关性的结论。
